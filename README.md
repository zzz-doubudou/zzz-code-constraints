# zzz-code-constraints

个人代码实现约束 Skill，用于在设计、计划、编码、测试、数据库脚本和代码评审阶段，持续约束 AI 保持实现简洁、可读、易维护。

本 Skill 以 `$karpathy-guidelines` 作为通用代码规范，并叠加个人开发约束。

## 核心原则

- 计划阶段明确说明涉及的文件、类、接口、方法、属性和字段。
- 只读取和修改与需求直接相关的代码。
- 代码实现保持简单、直接、可读。
- 禁止为一次性逻辑创建过度封装、包装层或扩展点。
- 能合并的方法优先合并，除非确实存在复用、独立契约、生命周期、复杂度或可读性需求。
- 所有新增或实质修改的类、接口、方法、属性、字段及其他成员都需要添加有效注释。
- 非显而易见的业务逻辑、状态变化、算法和兼容性处理需要添加注释。
- 业务体系中的交互优先使用代码、服务、API、SDK、CLI 或脚本。

## 测试代码约束

- 测试代码默认只用于本地验证，不提交 Git。
- C# 测试代码可以使用部分类单独存放，但遵循项目现有命名规范。
- 仅用于测试的服务、接口注册和入口代码必须使用 `#if DEBUG` 包裹。
- 生产业务代码禁止依赖或调用测试专用服务。
- 反射测试代码及其辅助方法放在测试文件或部分类文件的最底部。

## 代码组织

对于支持预处理器区域的语言，使用有意义的 `#region` 组织代码，例如：

- 字段
- 构造函数
- 属性
- 公共方法
- 私有方法
- 测试代码
- 反射测试代码

不为每一行或简单语句单独创建区域。

## 数据库脚本约束

- 允许添加主键。
- 禁止添加普通索引、唯一索引、聚集索引以及其他额外索引。
- 禁止添加外键约束和外键索引。
- 创建或修改数据库对象时，添加对应的数据库元数据注释。
- 至少为数据库、Schema、表和字段添加注释。
- 视图、存储过程、函数、触发器、序列和约束等对象也应根据数据库能力添加注释。
